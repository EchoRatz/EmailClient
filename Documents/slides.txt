Project: Network
Programming

  Design and Implementation of a
     Lightweight Email Client
   SMTP + POP3 + Socket Programming


      Complete the core functions ﬁrst.
    Advanced functions are bonus features.
Why This Project?
   ▶ A practical application of TCP socket programming.
   ▶ Learn how real application-layer protocols exchange
     commands and responses.
   ▶ SMTP and POP3 are simple, text-based, and still
     represent real Internet protocols.
   ▶ Build a complete client without reproducing a commercial
     mail system.


   Required scope: one account, plain-text email, SMTP sending,
         POP3 receiving, a simple Inbox, and local storage.
   Use a local or instructor-provided test server whenever possible;
          TLS/OAuth is not part of the basic requirement.

Basic Requirement 1: Send Email

   ▶ Connect to an SMTP server using a TCP socket.
   ▶ Let the user enter recipient, subject, and message body.
   ▶ Implement a small subset of SMTP commands:
        ▶ HELO/EHLO
        ▶ MAIL FROM
        ▶ RCPT TO
        ▶ DATA
        ▶ QUIT
   ▶ Parse and check server reply codes.
  Do not use a high-level library that completely hides SMTP in
  the required implementation.


                                                                  9 / 20
Basic Requirement 2: Receive Email

   ▶ Connect to a POP3 server and authenticate.
   ▶ Implement a small subset of POP3 commands:
       ▶ USER / PASS
       ▶ STAT or LIST
       ▶ RETR
       ▶ QUIT
   ▶ Display a simple Inbox:
       ▶ message number, sender, subject, and date when
         available;
       ▶ let the user select and read one message.




                                                          10 / 20
Basic Requirement 3: Local Mailbox


   ▶ Save downloaded messages locally.
   ▶ Reload saved messages after restarting the program.
   ▶ Storage can be simple: text ﬁles, JSON, or SQLite.
   ▶ A command-line interface is completely acceptable.
   ▶ Handle connection failures, wrong passwords, timeouts,
     and invalid responses gracefully.
   ▶ Keep a short log; never log passwords.

Testing and Deliverables
    ▶ Demonstrate successful connection to both SMTP and
      POP3 servers.
    ▶ Demonstrate at least three successful sent messages.
    ▶ Retrieve and display received messages.
    ▶ Save messages locally and reopen them after restart.
    ▶ Demonstrate at least three error cases.
    ▶ Brieﬂy measure normal send/retrieve time; a small table
      is enough and stress testing is not required.
    ▶ Submit individually:
        ▶ source code and README;
        ▶ one solution report;
        ▶ screenshots or terminal output;
        ▶ test results and representative logs;
        ▶ description of bonus features, if any.

Assignments

   ▶ All assignments are individual.
   ▶ Start early.

  Why start early?

  timeout, parsing, or environment issues. These problems are
  easier to solve when you leave time to test them carefully.
